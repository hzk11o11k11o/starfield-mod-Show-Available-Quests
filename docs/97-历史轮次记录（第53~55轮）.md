## 一·补三十四、第 49 轮（大项 E）：引擎内 harness —— 让判据自己跑

（完整设计与用法见 **`docs/09-测试驱动（harness）.md`**；本节记决策链、协议与验证。）

### 1. 起因与「先侦察再动手」

玩家的原话是三个痛点：**进游戏测试很麻烦 / 人工操作不一定覆盖所有测试要求 /
存档也不一定满足测试条件**。第一版方案想「扫写侧原生函数 RVA，DLL 直接调」，
侦察时被项目自己的结论挡住 —— `docs/04` 2.1 节：

> `r8` 在这些实现函数里是 **self（TESQuest）**……调用约定是 `rcx=VM, rdx=栈帧, r8=self`。
> **这也是为什么我们不能直接调它们（要造 VM 栈帧）**。

⇒ 改成「写侧动作全部放在 Papyrus（语言级 API）、DLL 只下命令 + 收回执」。
附带好处：**本轮不需要任何新的 RE/特征字节工作**，风险反而更低。

### 2. 三条关键设计（以及为什么）

| # | 决策 | 理由 |
| --- | --- | --- |
| 1 | 通道 = ESM **追加** 8 条 GLOB（0x806~0x80D），脚本用「自己任务 FormID 的前缀」动态 `Game.GetForm()` 取 | 避免改 VMAD（Object/Alias 联合体字节格式易错）；只追加 = 不碰旧记录号（存档按 FormID 记脚本实例） |
| 2 | `SAQ_TestHarness` 用 **0/1/2** 三态：0=关、1=DLL 请求启用、2=脚本已就绪 | 脚本初始化时会把「已执行序号」追平当前 Seq（防读档后重放旧命令）⇒ DLL 必须先等它就绪；再加上「提交前跳号」防「撞上已存在的 Ack」的假成功 |
| 3 | 界面测试入口 `SAQ_TestDrive*` **调用真实处理函数** | `ProcessUserEvent`（与玩家按键同一条链，含按钮启用判定）/ `onEntryPress`（与点击同一条链）/ `ScrollingEvent.SELECTION_CHANGE`（原版列表自己派发的就是它）—— 复制一套逻辑就等于测测试代码 |

顺带核对了官方 Interface 源码的按键语义：`MinimalButton.HandleUserEvent` 只在
**松开**（`!abPressed`）时回调 ⇒ DLL 送 `(事件名, false)`。

### 3. 落地的部件
