## 二、构建

```powershell
# 全流程（静态表 + DLL + SWF + 部署到 MO2）
& ".\tools\build-saq.ps1"

# 只重编 DLL + 部署
& ".\tools\build-saq.ps1" -SkipTable -SkipSwf

# 只重编 SWF + 部署
& ".\tools\build-saq.ps1" -SkipTable -SkipPlugin

# 只构建不部署
& ".\tools\build-saq.ps1" -SkipDeploy

# ★ 开发/自测（引擎内 harness）：DLL 含 harness + 部署用例文件 + ini Harness=1
& ".\tools\build-saq.ps1" -SkipTable -Harness

# ★ 发布构建：DLL **不含 harness**（当玩家跑 / 给 package-saq.ps1 打包用）
& ".\tools\build-saq.ps1" -Release -SkipTable -SkipSwf -SkipPapyrus
```

> **两种 DLL 构建模式**（第 53 轮，xmake option `saq_harness`，见 `plugin/xmake.lua`）：
> * 默认（`y`）= 开发构建：含引擎内 harness（ini `[Test] Harness` 控制是否激活）；
> * `-Release`（`n`）= 发布构建：`SAQ_Test*.cpp` 不参与编译，DLL 里没有任何 harness
>   字符串（实测小 ~12 万字节）；`package-saq.ps1` 打包时自动切到这一支。
> 切换会触发该 target 全量重编（约 5 秒~1 分钟，看增量）。

> 注意：**不要**用 `pwsh -File tools\build-saq.ps1` 外层再套一层 pwsh（会被 IDE 的
> safe-delete 包装挡下来），直接 `&` 调用即可。

### 打包（Nexus 上传包）

```powershell
# 打包（默认 v0.1.13；会自动做「发布构建 + 部署 → --release 校验 → 打包」，失败即终止）
# ★ 用户要求（第 62 轮）：包内配置强制为「正常玩」的默认值 —— [Test] Mode=0 / Harness=0
#   （组装 staging 时强制还原 + 校验），且包内不含任何测试资产（用例文件 / 结果 JSON）；
#   verify 有三层事后检查把守（源 ini / staging ini / 最新 zip 文件清单）。
& ".\tools\package-saq.ps1"

# 指定版本号 / 跳过校验
& ".\tools\package-saq.ps1" -Version 0.2.0 -SkipVerify
```

| 产物 | 说明 |
| --- | --- |
| `dist\SAQ-ShowAvailableQuests-<版本>.zip` | 上传包。zip 根 = mod 根：MO2 可直接「从压缩包安装」；手动安装 = 解压到 `Starfield\Data\` |
| `dist\nexus-description.md` | Nexus 介绍文案（中英），复制到 mod 页用 |

* ★ 第 53 轮起，打包强制走**发布构建**并跑 `verify_saq_build.py --release`：DLL 里
  **不允许**出现任何 harness 特征（出现即终止打包 —— 防「配置没切过去、带着测试代码打包」）。
  打完包后工作区/部署都是发布构建；回到开发构建：
  `& ".\tools\build-saq.ps1" -SkipTable -SkipSwf -SkipPapyrus -Harness`。

* 包内 `README.txt` 由 `resources\README-mod.txt` 生成（`{{VERSION}}` 自动替换为脚本参数）；
  素材（README / Nexus 文案 / ini 模板）都在 `resources\` 里，改文案改那里。
* 版本号三处需同步：`plugin\xmake.lua`、`plugin\src\main.cpp`（启动日志串）、脚本 `-Version`
  参数 —— 不同步时打包会点名提醒（不阻断）。
* ini 测试开关模板已入库（`resources\SAQ_ShowAvailableQuests.ini`）；`build-saq.ps1` 部署时
  「缺则补一份、已存在不覆盖」（保留测试时改过的 `Mode`）。

## 四、几处"踩过的坑"（改代码前请先读）

1. **commonlibsf 的头文件不自包含**：`RE/S/ScaleformGFxASMovieRootBase.h` 用到
   `Value` / `Movie` / `FunctionHandler`，**必须先 include**
   `ScaleformGFxMovie.h` / `ScaleformGFxValue.h` / `ScaleformGFxFunctionHandler.h`，
   否则报 C4430/C2061 一连串语法错误。
2. **不要 include `RE/E/Events.h`**：它的 `static_assert(sizeof(HitData) == 0xF0)` 在
   本项目里直接编译失败（缺 `HitData` 的完整定义）。需要 `MenuOpenCloseEvent` 时，
   改成每帧轮询 `UI::IsMenuOpen` 更省事（本项目的做法）。
3. **FFDec 的 `-importScript` 参数是"脚本目录"**，不是文件列表；
   直接把目录里**只放改过的脚本**（保持 `Shared/` 之类的相对路径），
   这样 SWF 里只有那几个类会被重新编译（体积只涨 1KB 而不是 13KB）。
   ★ 怎么确认「改的 AS3 真编进 SWF 了」：SWF 是 **zlib 压缩（头 `CWS`）**，
   直接 grep 二进制是找不到字符串的，要解压后再找：

   ```powershell
   python -c "import io,zlib;b=io.open(r'ui\missionmenu\build\missionmenu.swf','rb').read();print(b'SAQ_PeekGuide' in (zlib.decompress(b[8:]) if b[:3]==b'CWS' else b[8:]))"
   ```
4. **xEdit 的 Pascal 脚本必须纯 ASCII 且不能出现花括号**；
   取值要用 `GetEditValue()`（`GetElementEditValues(e, '')` 对叶子返回空串）。
5. `xSFEdit64.exe` 无头运行约 **5 分钟**（加载 1.4GB 的 Starfield.esm）；
   跑之前想清楚要导出什么，一次跑完。
6. ★ **Papyrus 编译器处理不了含空格的路径**：`PapyrusCompiler.exe` 拿到
   `D:\...\Show Available Quests\scripts\SAQ_Main.psc` 会报
   `filename does not match script name: saq_main`（把路径里的空格当成了参数分隔）。
   `build-saq.ps1` 的做法是先把 `.psc` 复制到 `%TEMP%\saq_papyrus\src`（无空格），
   编完再把 `.pex` 拷回来。参考项目也是这么绕的。
7. **ESM 的 FormID 必须保持稳定**：`esm\SAQ_ShowAvailableQuests.esm` **入库**，
   重新生成只能**追加新记录**（旧记录的顺序不能动）—— 存档按 FormID 记录脚本实例。
8. ★ **commonlibsf 里 `REL::ID` 为 0 的接口绝对不能调**（2026-09-19 实测踩雷）：
   `RE/IDs.h` 里值是 `0` 表示「这一版 commonlibsf 还没移植 / 没有 Address Library ID」，
   **不是**"未初始化"。一调用 `REL::ID::offset()` 就会 `REX::FAIL`，游戏里弹模态框：

   ```
   Failed to find offset for Address Library ID!
   The plugin needs to be updated and recompiled for the current game version.
   Invalid ID: 0
   Game Version: 1.16.244.0
   ```

   本次元凶：`RE::BGSStoryTeller::GetSingleton()`（它的 ID 就是 0），
   表现是**插件加载正常、一开任务菜单就弹框**（因为该调用在菜单打开的回调里）。
   防法：
   - `plugin/src/SAQ.cpp` 顶部的**编译期 ID 审计**（`kIdUsable()` + `static_assert`），
     把用到的每个 `RE::ID::x::y` 登记进去 —— 是 0 就直接编译不过；
   - 新增 commonlibsf 接口前，先看 `tools/commonlibsf-main/include/RE/IDs.h`
     里那个值是不是 0，是 0 就别用（换等价实现，或自己挖 ID / 硬编码 RVA）；
   - **间接依赖也要算**：inline 函数里藏的 ID 一样会炸
     （例：`BSFixedString` 的构造/析构 → `BSStringPool::GetEntry` / `Entry::Release`）。
9. ★ **要读游戏对象的字段时，先找「引擎自己怎么读它」**（2026-09-19 第 9 轮的经验）：
   Papyrus 的原生函数实现（`IsRunning` / `IsCompleted` / …）就是几行「读字段 + 测位」，
   反汇编抄下来比照着过时的头文件猜偏移可靠得多 —— 工具
   `python tools\re\quest_api_scan.py {strings|refs|regs|code|id}`，
   用法与全部证据见 `docs/04-运行时任务状态.md`。
   配套要求：**先核验对象身份（虚表 == 模块基址 + RVA），再读字段**；
   核验不过就整轮放弃过滤（宁可不滤，不能误滤），并把实测值写进日志。
10. ★ **写自己的插件文件（ESM）时，格式要从真实样品里抄，而且写完要能自校验**
   （2026-09-19 第 10 轮的经验）：别名/目标的字节布局来自 Starfield.esm 里挑好的样板记录
   （见 `docs/05`），`patch_saq_esm.py` 每次写完都重新解析 + 检查「记录正好填满 GRUP」。
   两个具体坑：① 组 size 要**重算**，不能用「原值 + 增量」（会把上一次写坏的错误继承下去）；
   ② 解析子记录必须处理 `XXXX`（4 字节扩展长度），否则长数据的记录会被解成一堆垃圾。
11. ★ **Starfield 的 Papyrus 与老滚/FO4 有几处不同**（第 10 轮实测）：
   没有 `AutoConst`（用 `AutoReadOnly`）、没有 `RegisterForUpdate`（用
   `StartTimer` + `OnTimer` 自己重排）。原版 API 源码就在
   `<游戏>\Data\Scripts\Source\Base\*.psc`，写脚本前先看真源码，别照搬老滚的记忆。
