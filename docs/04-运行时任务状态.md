# 04 · 读 TESQuest 的运行时状态（「已经接了的任务不显示」）

> 2026-09-19 第 9 轮。目标：需求里的
> 「任务必须是可接的」「已经接了的、进度没到的都不显示」。
> 第一层（静态过滤，剔内部任务）见 `docs/03`；第二层（玩家任务日志）在 AS3 侧；
> 这一篇记的是**第三层：引擎侧的运行时状态**。

---

## 一、为什么不能用 commonlibsf 现成的东西

| 想法 | 实测结果 |
| --- | --- |
| `RE::BGSStoryTeller::GetSingleton()` 读 runningQuests / queuedStartQuests | ❌ commonlibsf 里它的 `REL::ID = 0`，一碰弹模态框 `Invalid ID: 0`（第 2 轮踩过，见 `docs/01` 坑 8） |
| `RE::TESQuest::IsStageDone()` | ❌ `REL::ID = 0`（头文件里注释还写着 `// 112585`，那是**上古卷轴5**的 ID，没移植） |
| 猜 `TESQuest` 的结构体偏移 | ❌ 本项目已踩过三次「commonlibsf 偏移过时」（见 `docs/99` 风险表） |

**结论：偏移不能猜，要读引擎自己怎么读。**

---

## 二、做法：从 Papyrus 原生函数的实现里「抄判据」

思路：Papyrus 的 `Quest` 脚本有一批原生函数（`IsRunning` / `IsCompleted` /
`IsActive` / `IsStarting` / `IsStopping` / `IsStopped`）。它们的**实现就是几行
「读 TESQuest 某个字段、测某一位」的小函数** —— 把反汇编抄下来，就得到了
权威的字段偏移与位含义（引擎自己用的判据，不是我们猜的）。

### 2.1 怎么找到它们（工具：`tools/re/quest_api_scan.py`）

```powershell
cd "d:\workspace\starfield mod\Show Available Quests"

# 1) 函数名字符串在 exe 里的位置（名字都是唯一的）
python tools\re\quest_api_scan.py strings
#    IsRunning    .rdata rva=0x4bbe100
#    IsCompleted  .rdata rva=0x4d3fa90
#    IsActive     .rdata rva=0x4d3f9b8   …（还有 IsStarting/IsStopping/IsStopped 等）

# 2) 谁引用了这些名字（⇒ 原生函数注册代码）
python tools\re\xrefto.py "D:\SteamLibrary\steamapps\common\Starfield\Starfield.exe" 4bbe100
#    在 .text 里命中 3 处（全在一个「注册区」附近）

# 3) 把注册区翻译成「函数名 → 实现函数 RVA」表
python tools\re\quest_api_scan.py regs 0x20CC000 --len 0x2000      # -> ref/quest_natives2.txt

# 4) 反汇编实现函数，抄判据
python tools\re\disasm.py "D:\SteamLibrary\steamapps\common\Starfield\Starfield.exe" 0x20CDCA0 0 14
```

★ 注册代码的形状（本 exe 实测，`regs` 子命令就是照这个写的）：

```
mov rsi, [vtable + 0xF0]        ; 注册方法（虚函数）
mov ecx, 0x58                   ; NativeFunction 结构体大小
call operator new              ; 0x22C7320
lea r9, [rip+X]                 ; X = 实现函数（.text 里的几行小函数）
lea rdx, [rip+Y]                ; Y = 名字字符串（.rdata）
mov rcx, rax
call ctor                       ; 0x20CEDE0（带参数的原生函数）/ 0x20CF020（无参）
call rsi                        ; 注册
```

> 注意：`r8` 在这些实现函数里是 **self（TESQuest）**，不是第一个参数
> —— Starfield 的 Papyrus 原生函数调用约定是 `rcx=VM, rdx=栈帧, r8=self`。
> 这也是为什么我们不能直接调它们（要造 VM 栈帧），但**读同样的字段**没有任何限制。

### 2.2 抄出来的判据（`IsXxx` 的实现）

| 函数 | 实现 RVA | 判据 |
| --- | --- | --- |
| `IsCompleted` | `0x20CDC30` | `(flags >> 1) & 1` |
| `IsActive` | `0x20CDC20` | `(flags >> 11) & 1` |
| `IsRunning` | `0x20CDCA0` | `bit0 && !bit7 && [0x338]==0 && [0x32C]==0` |
| `IsStarting` | `0x20CDCE0` | `bit0 && (bit7 \|\| [0x338]!=0 \|\| [0x32C]!=0)` |
| `IsStopping` | `0x20CDD20` | `!bit0 && bit7` |
| `IsStopped` | `0x20CDD40` | `(byte[0x114] & 0x81) == 0` |

⇒ **TESQuest 的字段（相对对象起始）**：

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| `+0x114` | `uint32` | 运行时标志：bit0=已开始、bit1=已完成、bit7=正在停止、bit11=被追踪 |
| `+0x32C` | `byte` | 停止/换代的过渡标志 |
| `+0x338` | `qword` | 排队中的启动数据（启动流程用） |

> 与 commonlibsf 的声明对得上：它把静态 `QUEST_DATA` 放在 `0x108`（8 字节），
> 之后 `0x110` 起是「运行时数据区」，`0x330` 是 `startEventData`
> —— `0x114 / 0x32C / 0x338` 全落在这一段里，位置合理。

### 2.3 对象身份核验（不靠猜）

`TESQuest` 的虚表（`tools/re/rtti_slots.py --name "TESQuest@@"`，模块相对 RVA）：

```
0x4BD80D8   ← 主虚表
0x4BD8410   ← 次要（多继承的第二个 COL）
```

读字段前先比一下对象的虚表 == `模块基址 + 上面之一`；对不上就打
「未识别」并**放弃过滤**（见 `SAQ_QuestState.cpp`）。

## 三、代码里怎么用

* `plugin/src/SAQ_QuestState.h/.cpp`：读状态（`ReadQuestRuntimeState`）。
* 过滤判据 `IsAlreadyEngaged()` = **已开始 || 已完成** ⇒ 不是「可接」任务。
  （只被追踪但没开始的任务仍算可接 —— 玩家只是还没去做。）
* `plugin/src/SAQ.cpp` 的 `CollectAvailableQuests()`：两遍式 ——
  第一遍 `LookupByID` + 读状态 + 统计，第二遍按判据出候选。
* **安全阀**：虚表识别率 < 80% ⇒ 本轮**不过滤**，只把
  「未识别样本（名字 + 虚表值）」写进日志。宁可少滤，也不能误滤。

## 四、日志怎么自证（第 9 轮新增）

菜单一打开就会打一行：

```
运行时状态：引擎存在=202 虚表识别=202 未识别=0 已开始=3 已完成=0 追踪中=1 隐藏=3 过滤=生效 隐藏例: xxx（已开始 flags=0x1） …
```

与 AS3 侧那一行（同一份日志）交叉验证：

| 观察 | 结论 |
| --- | --- |
| `未识别=0` | 虚表判据正确，读的是真 TESQuest |
| `隐藏` ≈ AS3 `raw-keep` | 两层过滤说的是同一件事（引擎已开始的任务本来也在玩家任务日志里） |
| `隐藏=0` 且 `已开始=0` | 偏移/位判据错了，或对象不是 TESQuest ⇒ 看「未识别例」 |
| `过滤=跳过` | 虚表没认出来 ⇒ 日志里会给出实测虚表值，直接补进白名单 |

## 四点半、为了「进度没到」先攒的离线数据（DNAM 位）

`QUST` 记录 DNAM 的头 4 字节是任务标志位。**这一版的布局与 commonlibsf 的
`QUEST_DATA` 声明不一致**，实测布局是：

```
DNAM = uint32 flags @0 | uint8 priority @4 | 3 字节未用 | uint8 type @8 | 3 字节未用
```

（验证：`MQ101` 的 `dnam=0005010050…` ⇒ flags=0x00010500、priority=字节[4]=0x50=80
—— 与 xEdit 树状导出「Priority = 80 / Flags: Run Once, Warn, Unknown 16」逐字相符。）

当前 202 条候选的位分布（离线，`ref/quest_table_debug.json`）：

| 位 | 8 | 10 | 16 | 0 | 3 | 4 | 12 | 17 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 条数 | 145 | 87 | **157** | 5 | 6 | 5 | 1 | 1 |

`位16` 出现得最多（157/202），最像「引擎自动启动 / 常驻」类任务；但**没有证据前不当判据用**。
插件现在每次开菜单会打一行（`SAQ.cpp::FormatStaticFlagStats`）：

```
DNAM 位分布（候选 202 条）：位0=5 位3=6 位4=5 位8=145 位10=87 位16=157 位17=1
已开始样本: 平衡账目[DN=0x10100 已开始 flags=0x1] …（最多 6 条）
```

> 读法：如果「已开始」的那几条**清一色带位16**，那么「位16 = 引擎自己会启动它」
> 基本成立 —— 那样「有该位但引擎还没开始」就等于「进度没到」，可以直接在静态表上加一条过滤规则
> （纯离线数据，不需要再动引擎）。反过来，如果已开始样本里位16 一半有一半没有，就得找别的信号。
