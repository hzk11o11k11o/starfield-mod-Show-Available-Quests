> 2026-09-19 第 7 轮。起因：第 6 轮实测列表出来了，但内容是这样的——
> 「研究指示器 / 制造指示器 / 击杀地点上的目标 / 迪拜地标任务 …」，
> 485 条静态表里混着大量 B 社内部任务（指示器、任务板生成、地标、别名模板）。
> 本文记录**怎么把它们分出来**的（全部是离线可验证的信号）。

## 三、过滤规则（`gen_quest_table.py::filter_reason`）

按上面的顺序判断，命中即排除（返回原因标签，构建时打印统计）：

```
无本地化名（显示名 == EDID）      ← B 社没给正式名字 = 内部任务
名字含 [ ]
EDID 以 MB_ 开头                  ← 任务板生成任务（「接入口」以后单独做伪条目）
EDID/名字含 pointer / 指示器
EDID 含 landmark / 名字含 «地标任务»   ← ★ 第 81 轮：地标任务表里的 10 条豁免（见「六」）
EDID 含 tutorial
EDID 以 com_companion 开头（不分大小写）
原始 FULL 含 <Alias=              ← 名字靠运行时目标拼出来 = 生成任务
EDID 含 dialogue
EDID 含 handler / 名字含 «处理程序/杂项任务/的生成和场景任务/- 处理»
名字含 «各种系统» / «various systems»
名字以 : / ： 结尾
```

第 17 轮（DLC 支持）补的两条规则（实测来自 DLC 内容）：

```
EDID 含 _test / 名字含 «测试»            ← SFBGS00D_CruiseMode_TestSupport「巡航模式测试支援」
EDID 以 _companions 结尾                 ← SFTER_Companions「同伴任务处理」（与 COM_Companion* 同类）
```

> 判据用「`_test`」而不是「`test`」：后者会误伤 `contest` 这类正常词。
> 「测试内容」这条只命中 1 条、`_companions` 也只多 1 条（同伴系统类共 5 条），
> 说明 DLC 的垃圾分布与基础游戏基本一致，不需要为 DLC 另立规则集。

效果：**基础游戏 485 → 202 条**（排除 283；统计见构建输出）；
加上官方 DLC 之后总量为 **261 条**（破碎空间 22 / 地球舰队 22 / 自由航道更新 15）。

调试开关：`python tools\esm\gen_quest_table.py --keep-internal`（不过滤，用于对照）。

## 四、取舍与遗留

* **「彼方之力（地点）」被过滤**：它是主线神殿任务，但名字是别名模板（每个神殿一条），
  且引擎会自己引导玩家；不显示不损失信息。
* **任务板（MB_）的「入口」条目已做（第 27 轮）**：按需求「无限生成任务不显示、
  但接取入口（任务板）可以作为一条数据」——入口是 ACTIVATOR（`MissionBoardConsole*`），
  不是 quest，所以走**独立的入口表**（`plugin/src/SAQ_EntryTable.h`，由
  `tools/esm/gen_entry_table.py` 生成 12 条代表性入口：每个城市/据点一块）。
  uID = 引导目标 = 任务板在世界里的放置引用；默认模式下与普通条目一起显示，
  `ini Mode=5` 可只显示它们。详见 docs/99 第 27 轮与 docs/05。
* **静态过滤只是第一层**：它解决「内部任务混进来」；「进度没到不该显示」和
  「已经接了的不该显示（AS3 侧 QuestData 过滤已有）」要靠运行时那层，
  见 `docs/99` 的下一步清单。
* 规则是启发式的：目标是**宁缺勿滥**（漏掉一条真任务可接受，混进一条垃圾很扎眼）。

## 六、第 81 轮复查：「地球地标」系列（`landmark` 规则不准确）

> 2026-09-21。起因（玩家）：「我发现『地球地标』系列任务好像在可接任务列表里
> 一个都没有，检查一下」。

**复查结论：第 7 轮把 `Landmark_*` 判成「走近即完成、无从『接』」是错的。**

数据证据（`tools/esm/gen_landmark_quests.py` 的构建期核验，任何一条不符就构建失败）：

* 每条地标任务（Apollo / Cairo / Dubai / HongKong / London / LosAngeles / NewYork /
  Osaka / Shanghai / StLouis）都有一本对应的**书**（如 `Landmark_ApolloBook_NOCLUTTER`
  「利文斯通爵士的第二篇日志」）；
* 书上挂着官方脚本 `defaultrefoncontainerchangedto`，其 VMAD 属性
  `QuestToSetOrCheck` = 对应任务、`StageToSet` = **100** —— 即
  **书被拾取 / 购买（进入玩家物品栏）⇒ 任务 SetStage(100)**；
* 任务本身是 Activities（`QTYP = QuestTypeActivities`）、有 objective「访问 XX 地标 /
  找到雪景球」、可完成、有奖励（集齐 11 个给「旧地球」宇航服套装）。

⇒ 它们符合收录标准（「活动、可做完、有接取点」）。本轮处置：

| 项 | 做法 |
| --- | --- |
| 过滤 | `filter_reason(..., is_landmark=True)` —— `ref/landmark_quests.json` 里的 10 条**豁免**「地标」规则（其余规则照旧） |
| 引导 | 首选 = 书的**世界放置引用**（非常驻）→ 同 cell 常驻兜底（离书最近 ≤3 条）；Cairo 的书在书店库存里（无世界引用）⇒ 首选 = 书商 `AhnjongSinclairREF`（阿琼·辛克莱尔），兜底 = 该 worldspace 的**世界级常驻引用**（外景 cell 没有 per-cell 常驻组，同第 80 轮） |
| 说明 | 载荷最后两列（与势力开头任务同一通路）：写「去哪拿哪本书」（界面描述第一句） |
| London 特例 | 书有 20 处放置（书店 / 书堆）⇒ **只给说明**（`guide=false`，构建期清空候选）—— 与 CF01「深藏不露」同款「不可导航」通路 |
| Opportunity | 火星「机遇号」**不收**：没有可拾取的触发物（全 ESM 字节级复查：除任务自身外没有任何引用它的物品），由主线「发掘（Unearthed）」期间的博物馆展品互动触发 ⇒ 属主线流程内容 |

任务数变化：**261 → 271 条**（+10）；引导候选 **924 → 960**（9 条 × 4 个候选）、
有目标任务 **208 → 217**；内嵌回退载荷 202 → 212 条。

复现：

```powershell
python tools\esm\gen_landmark_quests.py    # 核验「书 → 任务」的 VMAD 关系 + 书的世界引用 + 兜底
python tools\esm\gen_quest_table.py        # 重建静态表（豁免过滤 + 引导 + 说明）
```

★ 运行时「已接取 / 已完成 ⇒ 隐藏」照旧生效：书一旦被拿起，任务就进了玩家日志
（`docs/04`），列表里自然不再出现 —— 这正是「可接任务」该有的行为。
