# 03 · 列表质量：把「内部任务」从可接列表里剔掉

> 2026-09-19 第 7 轮。起因：第 6 轮实测列表出来了，但内容是这样的——
> 「研究指示器 / 制造指示器 / 击杀地点上的目标 / 迪拜地标任务 …」，
> 485 条静态表里混着大量 B 社内部任务（指示器、任务板生成、地标、别名模板）。
> 本文记录**怎么把它们分出来**的（全部是离线可验证的信号）。

---

## 三、过滤规则（`gen_quest_table.py::filter_reason`）

按上面的顺序判断，命中即排除（返回原因标签，构建时打印统计）：

```
无本地化名（显示名 == EDID）      ← B 社没给正式名字 = 内部任务
名字含 [ ]
EDID 以 MB_ 开头                  ← 任务板生成任务（「接入口」以后单独做伪条目）
EDID/名字含 pointer / 指示器
EDID 含 landmark / 名字含 «地标任务»
EDID 含 tutorial
EDID 以 com_companion 开头（不分大小写）
原始 FULL 含 <Alias=              ← 名字靠运行时目标拼出来 = 生成任务
EDID 含 dialogue
EDID 含 handler / 名字含 «处理程序/杂项任务/的生成和场景任务/- 处理»
名字含 «各种系统» / «various systems»
名字以 : / ： 结尾
```

效果：**485 → 202 条**（排除 283；统计见构建输出）。

调试开关：`python tools\esm\gen_quest_table.py --keep-internal`（不过滤，用于对照）。

## 四、取舍与遗留

* **「彼方之力（地点）」被过滤**：它是主线神殿任务，但名字是别名模板（每个神殿一条），
  且引擎会自己引导玩家；不显示不损失信息。
* **任务板（MB_）本身的「入口」条目还没做**：按需求，「无限生成任务不显示、
  但接取入口（任务板）可以作为一条数据」——入口是 GameObject（终端），不是 quest，
  需要在以后做的「引导功能」里作为伪条目生成（指向最近的任务板）。
* **静态过滤只是第一层**：它解决「内部任务混进来」；「进度没到不该显示」和
  「已经接了的不该显示（AS3 侧 QuestData 过滤已有）」要靠运行时那层，
  见 `docs/99` 的下一步清单。
* 规则是启发式的：目标是**宁缺勿滥**（漏掉一条真任务可接受，混进一条垃圾很扎眼）。
