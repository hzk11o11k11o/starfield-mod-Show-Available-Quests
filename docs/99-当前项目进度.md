## 十二、已知风险

| 风险 | 说明 |
| --- | --- |
| **「已开始」≠「已接取」**（第 11 轮实证） | 引擎会把「玩家仍能接到」的任务提前置成 running（RAD05 全数到期，flags=0x8001）。TESQuest 的 started 位**不能**当「玩家已接」的判据；只有玩家任务日志（QuestData）算数 |
| **GLOB（float）存不下完整 FormID**（第 21 轮踩过） | GLOB 是 float（尾数 24 位）：完整 FormID > 2^24 后**奇数不可精确表示**（±1）。已把引导目标拆成「低 24 位（0x801）+ 高 8 位（0x805）」两个 GLOB。**以后再开 float 通道，先问「值会不会超过 2^24」** |
| **Papyrus 定时器在菜单开着时不走**（第 27 轮定案） | 任务菜单暂停游戏 ⇒ `StartTimer` 不触发：三次会话的 `引导已应用` 都精确落在「菜单关闭」时刻，菜单开着 27~37 秒零应用。**不要设计「菜单开着时脚本会处理」的功能**；引导总是「关菜单生效」（与原版 HUD 交互一致）。DLL 侧也据此不再在菜单开着时轮询确认（降噪） |

① `dist\` 里的 0.1.0 包是 **9/20 21:50** 打的 —— **缺**第 49 轮补丁②「候选降级观察期」

② 发布包不该含测试代码（第 52 轮自列的待办⑤）；③ 版本 0.1.0 → 0.1.1 + 文案/changelog。

### 2. 编译开关 `saq_harness`（plugin/xmake.lua 的 xmake option）

默认 `y`（开发构建 —— `build-saq.ps1` 默认行为不变）；`n` = 发布构建：
`SAQ_Test.cpp` / `SAQ_TestOps.cpp` **不参与编译**、`SAQ.cpp` 的三个调用点与
`SAQ_UI.cpp::InvokeUiTestDrive` 全在 `#if SAQ_WITH_HARNESS` 内 ⇒ DLL 里没有任何 harness
字符串（实测 **911360 B → 784896 B**）。四个 harness 文件自身也包了 `#if`（双保险：
即使被误加入编译也只编成空单元）。发布版发现 ini `Harness=1` ⇒ 打一行 WARN（不静默）。

★ 三个实测踩坑（别再退回去；都已写进 xmake.lua / build-saq.ps1 的注释）：
1. 「无条件 `remove_files` + 条件 `add_files` 加回」**不生效** —— 症状：SAQ.cpp 引用了
   `Test::*` 而 SAQ_Test.cpp 没参与链接（LNK2019 ×3：`Tick`/`LoadPlan`/`InstallLogRing`）；
2. `add_files(..., {exclude = …})` 在当前 xmake 版本下**也不生效** —— 症状：release 构建里
   SAQ_Test.cpp 仍被编译，而它引用了被宏排掉的 `UI::InvokeUiTestDrive`（C2039）；
   ⇒ 最终写法：`add_files("src/**.cpp")` 之后**只在关闭分支 `remove_files`**；
3. `xmake f` 只传 `--saq_harness` 会**把其它构建参数重置回默认**（实测 mode 从 releasedbg
   变回 release、产物跑到 `build\windows\x64\release\`）⇒ 构建脚本每次都带全套参数
   （`-p windows -a x64 -m releasedbg --vs=2022`）。

### 3. 三个入口

| 入口 | 行为 |
| --- | --- |
| `build-saq.ps1`（默认） | 含 harness 构建 + 部署（现状不变）；`-Harness` 再加「写 ini Harness=1 + 拷用例」 |
| `build-saq.ps1 -Release` | 发布构建 + 部署（不拷测试资产、不动 ini 测试键）；`meta.ini` 版本号同步 0.1.1 |
| `package-saq.ps1` | 1/5 发布构建 + 部署 → 3/5 `verify --release` → 打包；结束提示「回开发构建」的命令 |

### 4. verify 两种模式 + 部署一致性

`verify_saq_build.py [--release|--dev]`：默认按 DLL 内容自动探测（`harness：通道就绪`）；
发布模式 = **13 项反向检查**（`HARNESS_STRINGS` 表：出现任何一条即 MISS）+ 1 项正向
（`未编译 harness` 提示串在）—— 挡住「配置没切过去、带着测试代码打包」这个最危险的失败模式。
另加一条两种模式都查：**MO2 部署副本与工作区字节一致**（「构建了没部署」= 玩家跑的还是旧的）。

### 5. SWF / PEX / ESM 为什么两版相同

AS3 的 `SAQ_TestDrive*` 入口与脚本侧的测试命令执行器**保留**：它们只在「DLL 主动调用 /
写通道」时才起作用，而发布版 DLL 已无任何调用路径（改 SWF / PEX 的成本与风险不值得）。
ESM 的 8 条测试 GLOB 同理必须留在（追加记录，删不得）。
