## 二、这一轮（第 3 轮）做的事

用户反馈：*「看上去是乱码，里面也没内容」*（截图：第 8 个 tab 显示 `$SAQ_Avail…`，列表空）。

### 2.1 取证：一行日志定案

```
[21:00:27.120] 首次菜单打开：quest 总数=0 可接候选=0 推送=失败 (第1次)
```

- `推送=失败`：`PushToUI()` 里 `UI::GetMenuMovie("BSMissionMenu")` 返回 null（**没走到 Invoke**）；
- `quest 总数=0`：`TESDataHandler::formArrays[kQUST]` 读到空表；
- tab 标题是 `$SAQ_AvailableQuests` 原文：C++ 那份"按语言选好的标题"根本没送到，
  而 `$` 开头的 token 走的是游戏的 `translate_*.txt`，里面当然没有我们的 key。

### 2.2 离线逆向（全流程与命令见 **`docs/02-UI通道逆向.md`**）

反汇编 `Starfield.exe` 的 `UI::IsMenuOpen`（REL::ID 130475）拿到 ground truth：

- ★ **真实菜单表在 `UI+0x450`**（commonlibsf 标的 `menuMap@0x470` 在 1.16.244.0 上是错的）；
- 表头：数据指针 `+0x38`、容量 `+0x40`；条目跨度 `0x38`：
  key（string-pool 指针）`+0x00`、值 `+0x08`（0x28 字节）、nextIndex `+0x30`（`-1` = 空槽）；
- 哈希 = `keyPtr ^ (keyPtr >> 32)`，`index = hash & (cap-1)`，冲突沿 nextIndex 链；
- 值里 `+0x20` 就是 `Ptr<IMenu>`（`IsMenuOpen` 查它非空）。

### 2.4 设计要点（都是被坑出来的）

1. **不缓存、不复用 commonlibsf 的 UI/IMenu 偏移**，而是「实测偏移 + 扫描 + 校验」；
   校验用 RTTI 名字（虚表 → COL → TD → 修饰名）和「对象里存着自己的 menuName 指针」。
2. **只依赖一个虚函数槽**（`ASMovieRootBase::Invoke`），调用前还核对槽指针落在主模块里；
   数据改成一个字符串传（旧的数组式推送要 4 个虚函数槽）。
3. 每次尝试（宽字符/UTF-8 × 3 种函数路径）的结果都写日志，**一轮实测就能定位**。
