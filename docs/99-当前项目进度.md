[10:24:04.281] 引导请求：阿基拉城任务（0x002A4401）→ 引用 0x0012253A             ← 成功
[10:24:11.501] 引导请求：同情生者（0x010D5E84）→ 引用 0x0107BDB2（瓦鲁贮藏所）   ← 成功（首个 DLC 目标）

### 根因（都在 `SAQ_Guide.cpp::SetGuideTarget`）

| # | 错 | 后果 |
| --- | --- | --- |
| 1 | **自检上限写成 `16777215`（0xFFFFFF）** —— 那是「低 24 位」的上限，而 target 里存的是**完整 FormID** | 通道里一旦存过 DLC 目标（> 0xFFFFFF），**之后每次写入都被这个自检拒绝**（结果码 2）⇒「点亮瞬间取消 / 全都点不亮」 |
| 2 | GLOB 是 float（尾数 24 位），完整 FormID > 2^24 后**奇数不可精确表示**（±1） | 轻则 `GetForm` 取不到（状态 2），重则**指向相邻的另一条记录 = 错误的引导目标**（DLC 目标约一半是奇数） |

| 改动 | 说明 |
| --- | --- |

| 自检修正 | 有拆分 GLOB 时按分量检查（低 24 位 ≤ 0xFFFFFF / 高位 ≤ 0xFF）；旧 ESM 用完整 FormID 上限 0xFEFFFFFF |
| 遗留值兼容 | 修复前存档里残留的完整 FormID（prefix 还是初值 0）由 `CombineTargetFormID` 按旧语义识别，并在下一次写入时被新语义覆盖（不会卡死） |
| 日志 | 通道摘要 `目标=0x{:08X}`（拼好的完整值）；写入详情 `写入 SAQ_GuideTargetRef=0x… + SAQ_GuidePrefix=…（完整 0x…）` |

## 九、第 10 轮：任务引导（实现见 `docs/05`）

需求里的「能调用游戏的任务引导系统正常引导到接取任务的地点」这轮落地了整条链路：

```
AS3 选中条目按 Enter/X → SAQ_PeekGuide() "<序号>|<任务FormID>"
  → DLL 轮询（100ms）→ 静态表取「引导目标引用」→ 写 GLOB（SAQ_GuideTargetRef + GuideState=0）
  → SAQ_Main.psc 0.5s 轮询/菜单关闭 → GetAlias(0).ForceRefTo(目标) + SetObjectiveDisplayed(10)
                                    + SetActive(true)
  → 引擎画任务标记（蓝点）+ 扫描仪路径线
```

三个关键决策（每一个都留了证据）：

| 决策 | 为什么 |
| --- | --- |
| 引导目标 = **任务发布者的放置引用 / 任务自己的落脚引用**（离线算，83% 覆盖） | 引擎只认「世界里的一个引用」；发布者就是「去哪里接」的答案。地点地图标记（`LCTN.MNAM`）只有 7% 的任务有，做兜底 |
| **优先常驻（persistent）引用** | 非常驻引用要等格子加载，玩家在远方时 `Game.GetForm` 拿不到 ⇒ 引导失败。168 条里常驻 100 条 |
| 通道用 **GLOB**，并靠脚本写的**魔数 7777** 反查自己插件的加载序号 | SFSE 没有「C++ 直接给 Papyrus 发事件」的接口；FormID 的高 8 位运行期才知道，不能写死 |

顺带把**身份锚点**变成了证据链：日志里 `通知=7777` ⇒ ESM 已加载、代理任务在跑、脚本活着；
值在涨 ⇒ 脚本看得到菜单开关事件。

## 十二、已知风险

| 风险 | 说明 |
| --- | --- |
| **「已开始」≠「已接取」**（第 11 轮实证） | 引擎会把「玩家仍能接到」的任务提前置成 running（RAD05 全数到期，flags=0x8001）。TESQuest 的 started 位**不能**当「玩家已接」的判据；只有玩家任务日志（QuestData）算数 |
| **GLOB（float）存不下完整 FormID**（第 21 轮踩过） | GLOB 是 float（尾数 24 位）：完整 FormID > 2^24 后**奇数不可精确表示**（±1）。已把引导目标拆成「低 24 位（0x801）+ 高 8 位（0x805）」两个 GLOB。**以后再开 float 通道，先问「值会不会超过 2^24」** |
| **Papyrus 定时器在菜单开着时不走**（第 27 轮定案） | 任务菜单暂停游戏 ⇒ `StartTimer` 不触发：三次会话的 `引导已应用` 都精确落在「菜单关闭」时刻，菜单开着 27~37 秒零应用。**不要设计「菜单开着时脚本会处理」的功能**；引导总是「关菜单生效」（与原版 HUD 交互一致）。DLL 侧也据此不再在菜单开着时轮询确认（降噪） |
| **任务板入口多为非常驻引用**（第 27 轮） | 12 条入口里只有阿基拉城是 persistent：非常驻引用在 cell 未加载时 `Game.GetForm` 可能取不到（脚本报状态 2）。有成功先例（02025B99 / 002AD366），但**实测要盯 `脚本状态=2`**；若普遍失败 ⇒ Plan B：ESM override 给这些 REFR 加 persistent 标志 |
| ~~打开任务菜单偶发长停顿~~（第 11 轮发现 → 第 12 轮修复 → 第 16 轮确认） | 根因：失败解析路径里 `IsMapped`（VirtualQuery）累计 ~3.9 秒；`SafeRead` 改纯 `__try` 保护后消失。第 16 轮日志实证：收集 0 ms / 失败 0 ms / **无「主线程停顿」行** |
| **界面状态必须由回写驱动**（第 16 轮踩过） | `SaqToggleGuide` 只能在本地立即切状态，而「这条任务有没有引导目标 / 实际在引导哪条」只有 DLL 知道。凡是「界面先行、DLL 后处理」的动作都必须有回写通道（`SAQ_GuideReply`），否则界面会说谎 |
| **GLOB 锚点有次数窗口**（设计边界） | `SAQ_Notify` = 7777 + 菜单打开次数，认领窗口 7777..8776（1000 次）。单次会话极难超限；脚本重挂会把它重置回 7777（DLL 认领成功后不再读锚点，无影响） |
| **文本子记录必须带 NUL**（第 12 轮实证） | 非本地化 ESM 的 FULL/NNAM 等文本子记录，长度 = 字符数 + 1（含 NUL）。第 11 轮漏写 NUL ⇒ HUD「任务更新」显示 `[…]` |
| commonlibsf 的 `REL::ID = 0` 接口 | 已踩（BGSStoryTeller、`TESQuest::IsStageDone`）；编译期 ID 审计挡着（`docs/01` 坑 8） |
| **commonlibsf 的结构体偏移一律不可信**（第 18 轮升级为通则） | 已踩四次，其中 TESDataHandler 两次：`formArrays` 读到空表（第 5 轮，见 docs/02）、`files` 读到空链表（第 17 轮，四个 master 全被误判「未加载」⇒ 第 18 轮改前缀探测）。读引擎对象字段：先找「引擎自己怎么读它」（反汇编），或改用已实测可靠的引擎函数（`LookupByID` 等）；`TESGlobal::value`（0x48）是上一代项目修正过的 |
| **自己写的注释/文档也可能是错的** | 已踩：哈希指针、模糊 RTTI、误信「位16 = 自动启动」。结论要留原始反汇编/日志，且「改完要能被验证」 |
| **GFx 返回值要按类型读** | `GetNumber()` ≠ 万能（见 `docs/04` 2.4） |
| **TESQuest 运行时偏移来自反汇编** | `0x114 / 0x32C / 0x338` 有虚表核验 + 识别率安全阀；换游戏版本要重跑 `tools/re/quest_api_scan.py` |
| **非本地化插件的文本是内联的** | 本 ESM 的 TES4 flags = 0x01（无 Localized 位）⇒ 目标文本可以内联写 `<Alias=SAQ_GuideTarget>`，不需要动游戏的 strings |
| **非常驻引用** | 168 条引导目标里 68 条是非常驻引用：格子没加载时 `Game.GetForm` 可能取不到（日志会写 `状态=2`） |
| **patch 文件集 ≠ 源码目录** | 改任何 `.as` 都要在 `build-saq.ps1` 的同步清单里登记（普通 + lrg 两套）；lrg 源码由 `make_lrg_source.py` 生成 |
