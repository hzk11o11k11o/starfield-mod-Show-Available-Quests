## 三、这一轮做了什么（详见 `docs/02` 第七节）

### 3.1 根因 A：可见性判据用错了字段（空白的直接原因）

* 载荷里的 `iType` 是**任务真实类型**（0=活动/2=派系/3=杂项/4=任务），而
  `MissionsList.EntryFilterCompare_Impl` 算的是 `filterMask & (1 << iType)`；
  「可接任务」tab 的掩码是 `1 << 6` = 64 ⇒ `64 & (1 << 4)` **恒为 0** ⇒ 485 条全被滤掉。
  （上一轮把「全部」掩码改成 `0xFFFFFFBF` 去"第 6 位"也是同一个误解 —— 我们的
  `iType` 根本不是 6，那一位没被去掉。）
* **修法**：`iType` 保留真实类型（图标/类型文本要它），另加专用标记 `bSaqAvailable: true`，
  过滤时优先看标记 ⇒ 只在带 `AVAILABLE` 位的掩码（我们的 tab）下可见。
* **`MissionsList.as` 此前根本不在 patch 里**（构建只同步过 `MissionMenu.as` +
  `QuestUtils.as`）⇒ 补丁不进 SWF，改多少都是白改。`build-saq.ps1` 现在两个版本
  （普通 + lrg）都同步 `MissionsList.as`。
* 顺带 `SaqSafeType` 归一化 `iType`：派系(2) → 任务(4)。原版 `GetQuestIconLabel`
  对 2 落到 `default -> "None"`，而 `FactionSymbols` 未必有 "None" 帧 ——
  `gotoAndStop` 找不到帧会抛异常、把整行渲染带崩。
* `SaqSyncListMask`：重建列表前把 `filterMask` 与当前 tab 对齐（`BSScrollingTree`
  默认掩码是 `0xFFFFFFFF`，不对齐会让"未接任务只在我们 tab"失效）。

### 3.2 根因 B：C++ 推送 6 条路径全 fail

* `MissionMenu`（Embed 自 assets.swf symbol94）是**舞台上的子元件，不是 SWF 的 root**，
  而 `ASMovieRoot::Invoke(path)` 的路径解析**从 root 开始** ⇒ root 上根本没有这个方法。
* **修法**：SWF 侧 `onAddedToStage` 调 `SaqPublishEntryPoint()`，把
  `this.SetAvailableQuests` 挂到 root 上（名字 `SAQ_SetAvailableQuests`，
  MainTimeline 是 dynamic MovieClip 才能这么挂）；C++ 的 `kAttempts` 里把
  `SAQ_SetAvailableQuests` / `_root.SAQ_SetAvailableQuests` 放最前。
* 两条通路仍然解耦：桥不通也不影响界面（内嵌表兜底）。

### 3.3 已验证（离线）

* `docs/02` 第七节记了完整推导与代码；构建产物用 ffdec 反导出核对：
  两个 SWF 里都有 `bSaqAvailable` 判据、`SaqSafeType`、`SAQ_SetAvailableQuests`、
  内嵌载荷（`SAQ1`）。
