★ 三条结论：

1. **载荷完整送到了 AS3**：`_root.SAQ_Probe=6743|SAQ1\nT\t可接任务\tAvailable\nQ\t`
   —— 8561 字节 UTF-8（中文一字 3 字节）正好是 6743 个 char，且 24 字符前缀与载荷开头逐字相符。
   探针不再"含糊"，第 6 轮「参数到底有没有送到」的疑问到此终结。
2. **带 `_root.` 前缀的路径才通**：裸名字 `SAQ_Probe` / `SAQ_SetAvailableQuests` 全 fail。
   ⇒ `kAttempts` 已把 `_root.*` 排到最前（原来每次都要先白试两条）。
3. **"返回 0" 是 C++ 读错了**（见下），真实值 > 0 ⇒ **推送这一层是通的**。
   第 6 轮「调用 ok 但返回 0」的谜团是这个 bug，不是 AS3 解析失败。

## 三、第 8 轮修了什么

| 改动 | 位置 | 说明 |
| --- | --- | --- |
| **返回值按类型读** | `SAQ_UI.cpp::SafeReadValueNumber` | AS3 返回 `int` 时 GFx 的 Value 是 `kInt`，而 `GetNumber()` 会把联合体里的整数位**当 double** 读：202 → `1e-321`（打印 `0`，却仍 `> 0`）；`-1` → `2.12e-314`（也 `> 0`）⇒ **连 AS3 明确报的失败码都会被当成成功**。现在分 `IsInt/IsUInt/IsNumber/IsBoolean` 按类型取，并把 `-1`（载荷没送到）/`-2`（解析失败已回退内嵌表）翻译进日志 |
| **界面状态自证** | AS3 `SAQ_Report()` + C++ `CallAs3NoArg` | 推送后回读一行状态：`src/raw/keep/questData/list/mask/tab/lang/title/visible`，日志从此能证明"界面按什么数据在渲染"，不用再靠肉眼看游戏 |
| **日志转义** | `SAQ_UI.cpp::EscapeForLog` | 探针回读的字符串里带 `\n \t`，原样写日志会把一行劈成三行（上一轮日志就是三行拼一行）；现在转成可见的 `\n \t` 并截断 |
| 候选路径重排 | `kAttempts` | `_root.` 前缀优先（实测唯一命中），其余留作对照组 |

* 离线验证：`ffdec -export script` 反导出**部署目录**里的 SWF，确认 `SAQ_Report`、挂在 root 上的四个入口、`return -2` 都在（普通版 + lrg 版都查过）。
