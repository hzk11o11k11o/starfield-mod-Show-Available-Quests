## 二、第 9 轮：读到了引擎的任务运行时状态（本轮核心）

上一轮日志已经证明通道是通的，剩下两个真问题：**列表内容**与**运行时过滤**。

### 2.1 运行时状态：不猜偏移，抄引擎的判据

`commonlibsf` 的 TESQuest 基本是空的（`BGSStoryTeller::Singleton` 与
`TESQuest::IsStageDone` 的 `REL::ID` **都是 0**，一碰就弹 `Invalid ID: 0`）。

这一轮换了个路子：**Papyrus 的 Quest 原生函数实现就是引擎自己的判据**，
反汇编抄下来即可（工具 `tools/re/quest_api_scan.py`，完整证据见 `docs/04`）：

```
TESQuest + 0x114  dword  bit0=已开始  bit1=已完成  bit7=正在停止  bit11=被追踪
TESQuest + 0x32C  byte   停止/换代过渡标志
TESQuest + 0x338  qword  排队中的启动数据
```

* 判据来源：`IsRunning=0x20CDCA0`、`IsCompleted=0x20CDC30`、`IsActive=0x20CDC20`、
  `IsStarting/IsStopping/IsStopped`（全表见 `ref/quest_natives2.txt`）。
* 身份核验：对象虚表必须等于 `模块基址 + 0x4BD80D8 / + 0x4BD8410`（TESQuest 虚表）。
* **安全阀**：虚表识别率 < 80% ⇒ 本轮**不过滤**，只把未识别样本写进日志（宁可少滤，不可误滤）。
* 过滤判据：`已开始 || 已完成` ⇒ 不是「可接」任务。

### 2.2 界面状态「变化即记」

上一轮的 `状态:` 只在推送那一刻读一次 —— 那时玩家还没切到我们那个 tab
（实测 `tab=0 mask=0x-41`），所以「我们 tab 里到底几条」始终是空白。现在：

* C++ 侧菜单开着时每 500ms 读一次 `_root.SAQ_Report`，**内容变了才记一行**
  （切 tab、列表长度变化都会留证）；关菜单时补记最后一条状态；
* AS3 侧在「切 tab」和「重建列表」两个时刻各存一份快照，
  报告里多出 `last=... ourTab=... ourTabMax=...` —— 玩家只要**碰过**我们那个
  tab，之后切到哪都还能从报告里读出来。

### 2.3 顺手修掉的两处

| 改动 | 说明 |
| --- | --- |
| 掩码按无符号十六进制打 | 上一轮 `mask=0x-41` 其实是 `-0x41` = `0xFFFFFFBF`（补码），要人脑换算；现在直接打 `mask=0xffffffbf` |
| 报告长度上限 240 → 400 字节 | 新增快照字段后会超，超了会被截断成 `…` |

### 2.4 第 8 轮实测的三条事实（仍然有效）

1. **载荷完整送达**：`_root.SAQ_Probe=6743|SAQ1\nT\t可接任务\tAvailable\nQ\t`（8561 字节 UTF-8 = 6743 char）。
2. **路径必须带 `_root.` 前缀**（裸名字全 fail；`kAttempts` 已把 `_root.*` 排最前）。
3. **GFx 返回值必须按类型读**（`GetNumber()` 会把 int 当 double：202 → 打印 `0` 却仍 `>0`），
   已封装成 `SafeReadValueNumber`；第 8 轮日志里 `返回 202` 就是修正后的样子。
