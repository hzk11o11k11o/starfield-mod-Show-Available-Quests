## 一·补二十二、第 37 轮：SET COURSE（R）的星图真正落地 —— 第 36 轮那条 dispatch 被证明**引擎无 sink**

### 1. 定案（离线、可复现）：这类 `MissionMenu_*` 事件在 C++ 侧没有 sink

## 一·补二十四、第 39 轮：R（SET COURSE）**不再取消引导**（已引导的条目再按 R = 再开星图）

（完整技术细节见 **`docs/05-任务引导.md` 第十三节**；本节记决策与验证。）

### 1. 玩家反馈（原文）

> 「在可接任务 tab 中，R 键具有选中/取消选中任务条目的效果，这在其他 tab 中是没有的，
> 这就导致了如果一个任务已经被选中跟踪，再点 R 键，就是取消选择条目，而不会打开星图，
> 这应该是个多余的功能。原版游戏的表现是：在未选中的情况下，按 R，进入星图显示任务位置，
> 然后弹窗询问你是否要跟踪，如果已选中，则直接在星图中显示目标位置。」

### 2. 根因：三个调用方共用了「切换取消」语义

`SaqToggleGuide(entry, wantMap)` 原本「同一条再按一次 = 取消引导」。这对
**Enter（点子项「前往接取地点」= 原版「点目标切换追踪」）** 正确，但
**R / 手柄 X（`OnPlotCourseEvent`，SET COURSE）** 借用它之后：
已引导的条目再按 R = 取消引导（竖条灭 = 玩家眼里的「取消选中」），而且取消方向永远
`wantMap = 0` ⇒ DLL 不去开星图 ⇒「星图完全没打开」。

### 3. 修法（只改 AS3 一处；DLL / Papyrus / 协议都不动）

| 改动 | 说明 |
| --- | --- |
| `SaqToggleGuide(entry, wantMap, allowUntoggle = true)` | 第三参数 = 是否允许「同一条再按一次 = 取消」。传 false 时：同一条上再按 = **保持引导**，本次请求退化为「把这条再交给星图显示一次」（seq +1 / quest 不变 / wantMap = 1 / pendingClose = 1） |
| `OnPlotCourseEvent`（R / 手柄 X） | 传 `false`（**永不取消**）；`SaqPlotToLocationViaEngine()` 每次都发（第 37 轮已证明引擎无 sink，这条只剩日志证据 + 音效） |
| 未引导时 | 行为与第 37/38 轮完全一致：设引导 + 关菜单 + 开星图 |
| 取消引导的正路 | Enter 选中子项「前往接取地点」（param3 默认 true，切换语义保留） |

**为什么 DLL 不用改**：`PollGuideRequest` 的去重判据是**序号变化**（不是任务是否变化），
所以「同一条任务 + 新序号 + wantMap=1」会被照常处理：再写一遍通道（状态 5）→
回写 `SAQ_GuideReply(seq, 同一条, 0)` → 界面命中「实际值 = 本地值 且 结果码 0」分支 ⇒
`CloseMenu(true)` → 脚本再开一次星图。日志里两种按法可分辨：
`已设为引导:<任务名>`（首次）vs **`重复设定航线:<任务名>`**（已引导时再按 R）。

### 4. 与原版的差别（如实记录）

原版「未追踪时先弹窗问是否追踪」这一步**不做**：星图是
`Game.ShowGalaxyStarMapMenuAndPlotToLocation(Location)` 打开的（传**地点**，不是任务），
引擎没有「要不要追踪这条任务」的上下文；而我们的引导（蓝点 + 路径线）本来就要求先把
代理任务设为追踪。玩家可见的收益（按 R 就能看到目标星球 + 航线）不受影响。

### 5. 验证（已做）

* AS3 重编译 + 部署：`build-saq.ps1 -SkipTable -SkipPapyrus -SkipPlugin` ⇒
  SWF 725886 / 726145 B + MO2 部署完成；
* `verify_saq_build.py` **全部通过**（新增特征：两个 SWF 里的 `重复设定航线:` note；
  旧特征与反向检查全在）。

### 6. 待实测判据（下次进游戏）

1. 选一条有导航目标的可接任务按 R（首次）⇒ 与第 38 轮一致：暂停菜单整体关闭 →
   星图打开并画好航线（`星图：已打开（MapMenu 在屏幕上，R 后约 N 秒）`）；

## 一·补二十五、第 40 轮：R 的星图 —— 「开不起来」与「指错地方」两条线一起收

### 1. 玩家反馈与日志复查（对象：16:28 会话 + Papyrus.2）

反馈原文：**「R 键可以打开星图导航，但所有的任务都被导航至沃利阿尔法星」**。

复查发现的**硬事实**（这一轮就是从这里推理出来的）：

| 判据 | 证据 | 结论 |
| --- | --- | --- |
| 16:28:21 / 16:28:57 两次按 R | Papyrus 两次都执行到 `Game.ShowGalaxyStarMapMenuAndPlotToLocation(地点)`（地点分别是 `StationTheKeyInteriorLocation`（行星 Suvorov）/ `CityNewAtlantisLocation`（行星 Jemison）） | 脚本那一半**是好的**（地点、行星都正确） |

| 调用时刻 | 菜单关闭 16:28:21.298 → 同一秒内脚本就调了原生函数（0.5 秒定时器） | ⇒ 嫌疑：**调用正好落在「暂停菜单正在关」那一刻，被引擎丢掉** |
| 对照：15:55 会话（星图「开了，但要等好久」） | 脚本调用发生在菜单关掉 **4~5 秒**之后（当时定时器被冻结，玩家手动关了暂停菜单才跑） | 与上一条一致：**隔久一点调就有效** |

⇒ 修法（本轮 A）：**延时 0.5 → 1.5 秒** + **DLL 自动重试**。

### 2. 「指错地方」这条线：把引擎的「地点 → 星图节点」解析器挖出来（离线、可复现）

`ShowGalaxyStarMapMenuAndPlotToLocation` 的原生实现 `0x2010210` 第一步是
`0xac2ab0(&节点, 地点)` —— **拿「地点表单」查星图节点表**；节点值会原样进 UI 消息载荷
（`0x231f9b0` → payload = {dword0, 节点} → `0xC83790(queue, "MapMenu", kShow, 描述符, 载荷)`）。
查不到（节点 = 0）时，星图只会按**默认焦点**打开 —— 表现就是玩家说的
「显示的还是我所在的星球 / 指到沃利阿尔法星」（沃利阿尔法是玩家当时所在地）。

关键证据（新工具用法都在 `docs/05` 第十四节）：

* `0xac2c20`（节点匹配主体）：沿 `地点` 与 `[地点+0xC0]` 的链条比对节点表里的 LCTN 键；
* **`0x1FEACE0` 就是 `Location.GetCurrentPlanet()` 的实现**：它调 `0xac2ab0`，
  要求结果能查到 **PNDT(0xBA)** 记录，否则返回 null；
* ⇒ 「地点 → 行星」成立 ≠ 「地点 → 星图节点」成立（同一解析器的两种用途），
  所以「脚本日志里行星是对的」并不能证明星图会定位到那里。

### 3. 本轮实现（三层）

| 层 | 改动 |
| --- | --- |
| 脚本（`SAQ_Main.psc`） | ① `StarMapDelay` 0.5 → **1.5 秒**；② 地点候选三选一：**5 = 优先「行星自己的地点」**（`Planet.GetLocation()`，新默认）／6 = 引用当前/编辑地点原样（第 37~39 轮行为）／7 = 父地点链里第一个带行星的地点；③ 日志：`父地点[i]=…（ID=…，行星=…）` + `…候选号=N，采用地点=…（ID=…）`（带 `FormText/FormIDText` 两个小工具，避免 None 拼串） |
| DLL（`SAQ.cpp`） | ① **自动重试**：星图没开就每 2.5 秒重写一次「待处理 + 星图」状态（第 2/3 次顺带把状态改成 6/7 = 换地点候选），最多 3 次；只在「没有任何菜单开着」时重试（菜单开着游戏暂停、脚本跑不到）；引导目标变了/取消了就放弃；窗口每次顺延 12 秒。② **只读诊断** `LogStarMapDiagnosis`：每次按 R 把「引导引用 → 当前/编辑地点 → 逐层父地点 → 每层的节点解析结果（0 或不为 0）→ 玩家所在地点」写进日志 |
| 引擎函数调用 | 按项目惯例：RVA + **函数头 8 字节特征校验**（`4C 89 1C 24 49 89 5B 20`）+ `__try/__except` 包在**纯 POD 函数**里（MSVC 的 `__try` 不能与需要析构的对象共存） |

## 一·补二十七、第 42 轮：R 键「导航目标不是我悬停的那条」—— 先补证据、再修两条会改掉目的地的缺陷

### 1. 玩家反馈（原文）

### 3. 两条「会改掉目的地」的确定性缺陷（本轮修掉）

| # | 缺陷 | 机制（为什么会「不是悬停那条」） | 修法 |
| --- | --- | --- | --- |
| 1 | **DLL 星图重试抢跑**（第 40 轮遗留） | 重试从**请求时刻**起算 2.5 s 就把地点候选从 5 改成 6、7。而脚本自己拿到请求后：应用引导 → **再等 `StarMapDelay`=1.5 s** → 才调原生函数。⇒ ① 脚本还没跑到就换候选（候选 5 = 「行星自己的地点」**从未被试过**）；② 星图刚按候选 5 打开、随即被重画成候选 6/7 —— 玩家看到航线/焦点跳变（就是反馈里的「不稳定」） | 重试加**前置条件**：先看到脚本应用这次引导（`GuideState == 1`），从那一刻起再等 `kStarMapRetryAfterAppliedMs`=3 s（> 脚本 1.5 s 延时 + 余量）才允许换候选；菜单开着时照旧推迟 |
| 2 | **脚本的星图延时请求会失效**（第 37 轮起） | `StarMapPendingRef` / `StarMapPendingMode` 是脚本成员变量，只在「新的星图请求」时被覆盖。如果这段延时里玩家引导了**别的任务**（Enter 点「前往接取地点」/取消引导/接取后自动取消），待办仍指向**上一条**任务 ⇒ 定时器到点就把**旧任务的**航线开出来 —— 这正是「导航的目标不是我悬停的那条」 | ① `ApplyGuide` 里**任何一次新请求**先把待办作废（starMapWanted 分支再重新装上）；② 定时器到点做**过期校验**：`StarMapPendingFormID` 必须等于通道里此刻的目标 FormID，不等就跳过并 Trace `[SAQ] 星图请求已过期` |

## 十二、已知风险

| 风险 | 说明 |
| --- | --- |
| **「已开始」≠「已接取」**（第 11 轮实证） | 引擎会把「玩家仍能接到」的任务提前置成 running（RAD05 全数到期，flags=0x8001）。TESQuest 的 started 位**不能**当「玩家已接」的判据；只有玩家任务日志（QuestData）算数 |
| **GLOB（float）存不下完整 FormID**（第 21 轮踩过） | GLOB 是 float（尾数 24 位）：完整 FormID > 2^24 后**奇数不可精确表示**（±1）。已把引导目标拆成「低 24 位（0x801）+ 高 8 位（0x805）」两个 GLOB。**以后再开 float 通道，先问「值会不会超过 2^24」** |
| **Papyrus 定时器在菜单开着时不走**（第 27 轮定案） | 任务菜单暂停游戏 ⇒ `StartTimer` 不触发：三次会话的 `引导已应用` 都精确落在「菜单关闭」时刻，菜单开着 27~37 秒零应用。**不要设计「菜单开着时脚本会处理」的功能**；引导总是「关菜单生效」（与原版 HUD 交互一致）。DLL 侧也据此不再在菜单开着时轮询确认（降噪） |
| ~~任务板入口多为非常驻引用~~（第 27 轮发现 → 第 28 轮兜底 → 第 29 轮 override **被实机否定** → **第 30 轮新建常驻引用治本**） | 12 条入口里只有阿基拉城是原生常驻 ⇒ 其余 11 条在 cell 未加载时 `Game.GetForm` 取不到。★ **第 29 轮的 override 路线不成立**：override 只换数据、**不改变引用的加载分类**（官方 70 条同类 override 原记录本来就全是常驻 = 零先例；实机 12:45 会话 `可导航 2`）。第 30 轮改为**新建** 11 条常驻 XMarker（0x900~0x90A，位置 = 板坐标）+ 候选链。★ **第 33 轮补齐最后一块**：官方对同一条 cell（SFBGS003 → 霓虹城）的写法 = **空壳 CELL 记录（EDID + flags 0x4000）+ 紧跟 CellChildren 组** —— 我们也照抄了（11 条，xEdit 验证通过；**待实测 `marker 11`**）|
| ~~override 世界引用的冲突面~~（第 29 轮引入 → **第 30 轮已消除**） | 第 29 轮对 11 条任务板 REFR 的 override 已全部移除 ⇒ 不再覆盖任何基础游戏记录。第 30 轮只往那些 cell **新增**自己的记录（mod 加物件级操作），与改同一 cell 的 mod 无冲突 |
| ~~打开任务菜单偶发长停顿~~（第 11 轮发现 → 第 12 轮修复 → 第 16 轮确认） | 根因：失败解析路径里 `IsMapped`（VirtualQuery）累计 ~3.9 秒；`SafeRead` 改纯 `__try` 保护后消失。第 16 轮日志实证：收集 0 ms / 失败 0 ms / **无「主线程停顿」行** |
| **界面状态必须由回写驱动**（第 16 轮踩过） | `SaqToggleGuide` 只能在本地立即切状态，而「这条任务有没有引导目标 / 实际在引导哪条」只有 DLL 知道。凡是「界面先行、DLL 后处理」的动作都必须有回写通道（`SAQ_GuideReply`），否则界面会说谎 |
| **GLOB 锚点有次数窗口**（设计边界） | `SAQ_Notify` = 7777 + 菜单打开次数，认领窗口 7777..8776（1000 次）。单次会话极难超限；脚本重挂会把它重置回 7777（DLL 认领成功后不再读锚点，无影响） |
| **文本子记录必须带 NUL**（第 12 轮实证） | 非本地化 ESM 的 FULL/NNAM 等文本子记录，长度 = 字符数 + 1（含 NUL）。第 11 轮漏写 NUL ⇒ HUD「任务更新」显示 `[…]` |
| commonlibsf 的 `REL::ID = 0` 接口 | 已踩（BGSStoryTeller、`TESQuest::IsStageDone`）；编译期 ID 审计挡着（`docs/01` 坑 8） |
