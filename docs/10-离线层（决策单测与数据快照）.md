# 10 · 离线层：决策单元测试 + 数据管线黄金快照（第 64 轮 · 大项 K）

> 一句话：**harness** 覆盖「引擎时序」（真实，但要开游戏、只能跑固定脚本）；
> **本层**覆盖「决策组合爆炸」（毫秒级、零游戏）。两者互补，缺一不可。

## 一、为什么要有这一层

- 过滤 / 门槛 / 候选池 / 引导复算的判据以前**只存在于引擎调用点里**：想验证
  「条件组合」只能进游戏造状态（harness 一轮要几分钟，还要读档 / 传送配合）；
- 而这些判据的组合空间很大：三态（真 / 假 / 未知）× 对话组 × 候选数 × 观察期状态
  × testMode —— 用引擎去枚举这些组合既慢又不稳定；
- ⇒ 把**判据**从「查引擎」里剥成**纯函数**，在 PC 上枚举断言（602+ 条，毫秒级）。

## 二、结构

| 位置 | 内容 |

| `plugin/tests/MiniTest.h` | 极简测试框架（自写、零依赖：注册 + 断言 + 计数 + 退出码） |

## 三、纯函数清单（改谁 ⇒ 配谁的测试）

| 纯函数 | 原调用点 | 被单测钉死的语义 |
| --- | --- | --- |
| `DeriveRuntimeFlags` | SAQ_QuestState.cpp | bit0/1/7/11 与 IsRunning 全判据（64 组合枚举） |
| `IsCompletedConfirmed` | 两处共用 | 「已完成 + 虚表已知」（与过滤判据**同源**） |
| `DecideRuntimeFilter` | CollectAvailableQuests | 只挡已完成；虚表未知**不剔** |
| `RecognizedPct` / `RuntimeFilterApplied` | 同函数的安全阀 | 80% 门槛；空表 ⇒ 100（不因安全阀放弃） |
| `DecideProgressGates` | EvaluateProgressGates | 一条非 pass 即返回（fail 优先于 unknown）+ 越界 kUnknown |
| `DecideInfoGates` | EvaluateInfoGates | 组间「任一对话可用即放行」；越界检查的**顺序短路**（有意保留） |
| `PickCandidate` | PickGuideCandidate | 第一个可得即最优；空 / 全不可得 ⇒ {0,false} |
| `AllCandidatesNonPersistent` | 同名（needsApproach） | 空池 ⇒ false；任何常驻 ⇒ false；位定义固定 |
| `DecideGuideRecalc` | UpdateQuestGuideTarget | 降级要过观察期 / 升级立即 / 恢复清观察 / 无候选永不降级 |
| `PassesTestFilter` | 同名（testMode） | 模式 0~6 真值表 + 未知值不过滤 + 模式 5 不在此处理 |

## 四、用法

```powershell
& ".\tools\test\run-all-tests.ps1"              # ① 单测 + ② 快照（秒级，退出码 = 结果）
& ".\tools\test\run-decision-tests.ps1"         # 只跑单测（-SkipBuild 只跑不建）
python tools\test\golden_snapshot.py            # 只校验快照（有变化 ⇒ 退出码 1）
python tools\test\golden_snapshot.py --list     # 看当前产物摘要（不校验）
python tools\test\golden_snapshot.py --update   # 有意变更后更新快照（随后审查 git diff）
```

## 五、改决策逻辑的正确顺序（重要）

1. **先**改 `SAQ_Decision.*` 的纯函数 + 改 / 加对应单测期望 ⇒ 跑单测，**看它先红**
   （红 = 测试确实钉住了行为）；
2. **再**改引擎侧调用点（`SAQ.cpp` / `SAQ_QuestCond.cpp` / `SAQ_QuestState.cpp`）；
3. 跑 `build-saq.ps1` + `verify_saq_build.py`；（可选）进游戏跑一遍 harness 用例回归。

反向阅读：想知道「某判据到底是什么」⇒ **先看纯函数 + 单测**（它们是可执行的规格），
不要从 6000 行的 SAQ.cpp 里猜。

| `esm/SAQ_ShowAvailableQuests.esm` | patch_saq_esm.py 等 | 3947 B（幂等：重跑构建字节不变，已实测） |

**规范化**（对内容敏感、对形式钝感）：
* `.json` → 解析后 `sort_keys` + 紧凑分隔符再哈希 ⇒ 改缩进 / 键序**不算**变化；
* `.h` → 去块注释与行注释、逐行 strip、去空行再哈希 ⇒ 改注释**不算**变化；
* 其它（ESM）→ 原始字节。

**自测已验证**（第 64 轮）：格式级改动（缩进 + 键序）⇒ 仍绿；内容级改动（改一个值）
⇒ 报红（退出码 1）；恢复 ⇒ 转绿。

## 七、边界（本层不做什么）

- **不**做「管线真实重跑」对比（fetch/scan/gen 全链 3~6 分钟、依赖游戏数据）——
  重跑构建后跑一次本快照即可；要审查生成逻辑改动，看快照 diff 的摘要变化；
- **不**替代 `verify_saq_build.py`（产物特征 / 部署一致性）与 harness（引擎时序）——
  三者分工：本层 = **逻辑 + 数据**，verify = **产物**，harness = **时序**。
