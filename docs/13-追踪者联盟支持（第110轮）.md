## 二、medium 档的 FormID 方案（本轮的运行期核心）

**实测布局**（证据 = SFBGS003.esm 的文件内记录）：
```
medium：FormID = 0xFD000000 | (mediumIndex << 16) | local(16 位)
  - 文件内 index = 0（占位），运行期由引擎按加载顺序分配（8 位、最多 256 个）
  - 实测样本：自己的记录 0xFD00004A / 0xFD00492D（local < 0x10000）、
    cross-ref 0xFD000EF5（FTYP 引用自己空间的关键字 FactionTypeTrackersAlliance）
对比：full = prefix<<24（prefix 0x00..0xFC）；light = 0xFE000000 | (idx<<12) | local(12 位)
```
**落地**（`plugin/src/SAQ_Masters.{h,cpp}`）：
* `Master` 加 `medium` 字段；`Tier{Full, Medium, Light}` 统一候选；
* `CandidateFormID/Prefix` 三档分支；`MakeFormID` 按档位取位宽（24/16/12 位）；
* **探测（前缀探测·阶段 1）改为「full + medium 同一样本一起扫」** ——
  medium 的 16 位记录号在别的 full 插件里可能撞号（误命中）⇒ 只凭 full 命中不能判「未加载」；
  两个 tier 都收候选，交给阶段 2 的全量命中率区分（≥90% 才认定）；
  light 空间保持在「前两段全空才扫」；
* **`kMaxFullPrefix` 0xFD → 0xFC**（0xFD 段留给 medium）；
* 日志：`SFBGS003.esm 序号=0x??(medium) 前缀=0xFD|0x??<<16 记录命中 2/2`（探测成功形态）。
