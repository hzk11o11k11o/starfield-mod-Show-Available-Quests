; ============================================================================
;  SAQ 引擎内自动化测试 —— 用例计划（第 49 轮 harness；第 54 轮补齐历史判据）
;
;  怎么用：
;    ① 把本文件放到 mod 目录的 SFSE\Plugins\ 下（build-saq.ps1 部署时会自动拷过去）；
;    ② ini（SFSE\Plugins\SAQ_ShowAvailableQuests.ini）里设 [Test] Harness=1；
;    ③ ★★ 顺序不能反：**先构建 + 部署完成，再启动游戏**（第 50 轮实测定论）——
;       Starfield 的 UI 资源在游戏启动阶段加载，进程起来之后再部署的 SWF 不会被采用；
;    ④ 启动游戏并**读一个存档**（随便哪个，用例会自己把需要的那几条任务回滚）；
;    ⑤ 等日志出现 `harness：全部用例结束`，看 mod 目录里的 SAQ_testresults.json。
;       （判定游戏加载的 SWF 版本：看日志 SAQ_Report 输出有没有 `stamp=` 字段；
;        第 54 轮起 = `stamp=53`。）
;
;  语法：`[case:名字]` 开一个用例；`desc = 说明`；`step = <操作> [参数]`。
;  ★ 会改任务状态（Reset/Start/SetStage/CompleteQuest）与**传送玩家**—— 先备份存档，
;    别在主力存档上跑。
;  ★★ **ini 的 `[Test] Mode` 建议用 0（显示全部）** —— 本文件全部用例在 0 下成立。
;    个别测试模式的差异（历史轮次实测用的 Mode）：
;      · Mode=6（只显示「需要靠近」的任务）⇒ 列表里**没有**「营救机器人」（第 47 轮
;        起它有了常驻兜底）⇒ r45 会找不到条目；r47 的入口统计也会是 0（入口条目
;        只在 Mode=0/5 时追加）；
;      · Mode=5（只显示入口条目）⇒ r47 可用，但 r26/r44/r45/r48 看不到任务行。
;  ★ 造状态的步骤必须在 menu.open **之前**；断言引导结果必须在 menu.close **之后**
;    （Papyrus 的轮询节拍在菜单开着时冻结，第 27 轮实测定论）。
;  ★ 两条容易踩的语法点（第 54 轮新增）：
;    · `assert.log/assert.nolog` 的 `scope=`：默认只找「本步骤开始之后」的行 —— 而
;      动作与它的日志常落在**同一次 Tick** 里（产品路径先跑、harness 后跑）⇒ 断言
;      「上一步引起的那一行」要用 `scope=prev`，查整条用例的总账用 `scope=case`。
;      ★ 第 55 轮实测教训：smoke 的三条断言因为漏写 `scope=prev` 出现过**假失败**
;      （"引导请求"行其实早就打了，只是落在断言窗口起点之前）—— 凡是断言「上一步
;      动作引起的那一行」，一律写 `scope=prev`。
;    · ★★ 第 56 轮（09:22 会话实测的**驱动 bug**，已修）：驱动器曾经在每一步结束时
;      把日志窗口起点清 0 ⇒ 所有 `scope=prev` 断言退化成「整个环形缓冲」——
;      既会匹配到本会话最早那几行（**假 PASS**：r26/r44/r47/r48 四条用例都中招），
;      又会把早就翻篇的行当成「不该出现」（r48 的**假 FAIL**，报文里那句
;      「窗口从 idx 0 起」）。现在窗口起点按步保留，另有兜底（起点 0 ⇒ 退到用例起点）。
;      判据：日志里那行 `harness：已启用（… 驱动器 v57：…）`（v56 及更早 = 旧驱动器）。
;    · `teleport*` 步骤的回执要等 **cell 加载**才算完（实测 4.3 秒）⇒ 旧的 3 秒窗口把
;      「传送成功」判成 FAIL。驱动器现在给传送 **20 秒**（其余命令仍 3 秒）。
;    · `~0x…` = **记录号**（不是运行期 FormID）：DLC 任务的运行期高字节是加载顺序
;      （本机 SFBGS050 = 0x03，换机器可能不同）⇒ 用例里写 `~0x0008EBDC`，由驱动器
;      按静态表解析。基础游戏的任务（master 0）两种写法等价。
;
;  ★★ 第 57 轮（09:35 会话实测的**驱动/用例**问题，三件都已修 —— 产品侧全对）：
;    · `ui.select/selectchild/expand` 的 `~0x…` 参数漏写回 ⇒ 被当成记录号 0x000000
;      （r45 的 `ui.selectchild ~0x0008EBDC` 报「静态表里没有记录号 0x000000」）。
;      驱动已修（v57）；用例写法不变。
;    · **两条断言依赖同一批行时，第二条要写 `scope=case`** —— `scope=prev` 的窗口
;      起点 = 上一步**开始**时刻，会被上一条断言「消耗」掉：同一 Tick 早先打印的行
;      落在窗口之外（09:35 会话 r48 的 `INFO没到:` 与 r26 的 `引导确认：菜单还开着`
;      两条断言就是因此假 FAIL）。
;    · **开菜单后要等「推送成功」再动界面**（本机开菜单的第一次推送常因桥解析失败、
;      0.8 秒后才重试成功）：不等就会撞上「列表还是内嵌回退数据（202 条、不含任务板
;      入口）」⇒ `ui.selectchild` 报 `err|notfound`（09:35 会话 r47 的真因；证据 =
;      界面报告 `src=embedded` / `raw=202`）。
;    · 「按过 R（XButton）」的用例结束后，驱动器会开一段 **4 秒延迟复查窗口**：
;      星图由脚本在菜单关闭后 1~1.5 秒才打开 —— 清场当时查不到它，它会落在下一条
;      用例开头把游戏暂停（09:35 会话 r26 的 `ping` 因此超时 3 秒）。
;  ★★ 第 58 轮（10:31 会话实测的**游戏端**现象，驱动器已加防护与诊断）：
;    · 现象：连续两次传送挨得太近（回执后 38 ms 就提交下一条 MoveTo）⇒ 第二次加载
;      **永远没结束**：Papyrus 日志停在那一刻（VM 卡在 MoveTo 里）、界面停在
;      「右下角加载转圈 + HUD 任务蓝点」，之后所有命令都没有回执。
;    · 驱动器 v58 的防护：传送步骤要等**落地静默期**才结束 —— 加载画面
;      （LoadingMenu/FaderMenu）先消失，再连续静默 1.5 秒，且距回执 ≥3.5 秒
;      ⇒ 传送步骤的耗时比过去多 2~5 秒，属正常。
;    · 诊断：命令超时/落地等待会把「此刻打开的菜单」写进日志与结果 JSON ——
;      里面出现 LoadingMenu/FaderMenu = 游戏卡在加载画面（不是脚本 VM 的问题）。
;    · 卡死自动中止：确认卡死（有加载画面，或连续 2 次命令无回执）⇒ 剩余用例标 SKIP
;      并写明原因，不再逐条陪跑超时；同时用一条 Ping 冲刷通道（防游戏恢复后执行
;      那条排队的传送）。
;  ★ 本文件里的用例会**传送玩家**（teleport.entry）—— 它会改变你当前所在位置，
;    跑完想回到原处请自己读档。
