第 38 轮：修「R 键现象混乱」—— kHide 只关子菜单的坑 + 星图目的地诊断

玩家反馈：有时候只是切到了最外层主菜单 / 星图要等好久 / R 不会选中任务 /
星图显示的还是我所在的星球、没有导航点 / 有一次打开了其他任务的位置。

实测日志（15:52~15:55 会话，第 37 轮版本）定案：
- 三次按 R 同构：kHide 后「菜单已关」+ 脚本应用了引导，但脚本的 0.5 秒定时器
  实际 4~5 秒后才跑（星图也那时才开）；2.5 秒单点探测每次都提前判「没有打开」= 假结论。
- 根因：Starfield 的暂停菜单（注册名 PauseMenu）是任务菜单的父级 —— 只 kHide
  任务菜单会停在暂停菜单顶层（= 玩家看到的「最外层主菜单」），游戏没恢复运行 ⇒
  Papyrus 定时器不走（第 27 轮定案）⇒ 星图要等玩家自己关掉暂停菜单才出现。
- 名字纠正：exe 菜单名表（.rdata 0x4D7DF00 一带）里是 PauseMenu（外层）+
  BSMissionMenu / MapMenu / SkillsMenu…（tab），没有 DataMenu（那只是 AS3 事件前缀）。

修法（三层）：
- AS3：SaqPendingCloseToGame（与 SaqGuideWantMap 同生共死）；C++ 回写成功后
  走原版「退回游戏」路径 CloseMenu(true)（StartGameRender + 关闭动画 →
  OnTimelineCloseEvent → SaveMenuState + GlobalFunc.CloseAllMenus()）整个暂停菜单
  一步关完；被拒绝则不关。SAQ_PeekGuide 变四段（第四段 = 界面会自己关菜单）。
- DLL：peek 第四段 → ApplyGuideRequest(..., swfCloses) → RequestStarMapOpen：
  新协议不发 kHide；星图探测改多段窗口（1.5 秒记「还开着哪些菜单」+ 星图一出现记
  「R 后约 N 秒」+ 12 秒才 WARN）。
- Papyrus：OpenStarMapFor 日志带行星（GetCurrentPlanet）；地点没行星时沿
  GetParentLocations() 往上找第一个带行星的地点再传给引擎（顺带修 parent 变量名
  触发 Papyrus 遮蔽报错的坑）。

验证：全量构建 + 部署；verify_saq_build.py 全部通过（新增 SWF 关菜单 note；
DLL 新协议/等待中/菜单名单/耗时/PauseMenu；PEX 行星诊断/父地点兜底/两个 API；
反向检查旧单点探测文案已替换）；Nexus 包重打（1,772,157 B）。
